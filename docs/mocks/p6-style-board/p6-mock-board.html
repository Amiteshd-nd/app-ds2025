P6 UI mock board

Three zoomed mocks for your OK: the phone home screen, one app (UPI), and the Act 0 airport HUD. Everything is drawn at the game's real 640×360 resolution and scaled up with no smoothing, so each square is one game pixel. All text uses Pixelify Sans, snapped to whole pixels the way the bitmap font will be.

Calls I made as art director

Phone rises from the bottom, full heightAt 90% height the 4-column grid gives 37pt tap targets on an iPhone 15. Making the phone 200px wide and letting its chin run off the bottom edge gives 46×62 game-px cells, which is 50×68pt. It also reads like the phone is being lifted into view.
Grid is 4×3, plus the dock14 apps: dock (Maps, Chats, UPI, Camera) + Calls, Contacts, News, Reels, Calendar, Jobs, Food, Dating, Notes, Settings. Calls and Reels come from the existing apps.json. A 4th row comes back when Acts 2–4 add apps.
UPPERCASE for labels, mixed case for contentUppercase Pixelify runs about 6.5px a letter, so ledger lines and dialogue stay mixed case to fit in 40 characters. Titles, app names, tags and buttons are uppercase.
Image 4 shapes the HUD platesFrom the party-plates reference: chunky rounded plates with a 1px drop shadow, bold white text and speech-bubble tags for prompts. Fills stay black at 85% with a grey border, as your spec says. Colour only means something: the NEW tag, the wallet tick, the unread badge.
Drawings small, touch zones bigA choice pill is 18px tall on screen, but its touch zone is at least 44 game px (48pt). Same for the phone button and the ★. The game is letterboxed sideways in landscape, so only the bottom home-bar strip (about 20px) needs a margin.
A separate UI palette12 locked UI colours in their own ui-palette.gpl, used through c.map.*, c.phone.* and c.hud.* tokens. The world art keeps its 48 colours, and the HUD star reuses the world's auto yellow.

Font and UI palette

Font finding: four glyphs redrawnPixelify Sans is designed with a 5 that looks like an S and a Z that looks like a 2. That's risky for prices and clocks (₹4,500 read as ₹4,S00). Its comma is thinner than one game pixel, so it shows as a full stop, and it has no ₹. The bitmap font keeps every other Pixelify glyph and swaps in hand-drawn 5, Z, comma and ₹, as you can see above. The OFL allows modified versions, and Pixelify Sans reserves no font name. I'll still label ours "based on Pixelify Sans" and ship it under the OFL.

P6a plan, once you say OK

  1. Log decisions. ADR-113: no minimap; the map is a fullscreen overlay only, and the minimap setting is removed. ADR-114: UI style board, Pixelify Sans (OFL font file only), a 12-colour UI palette, plus the art-director calls above.
  2. Font pipeline. Add scripts/import-font.mjs: TTF → Phaser BitmapText at 11px (regular and bold) and 22px, a hand-drawn ₹, a threshold with no anti-aliasing, and integer scales only. Ship OFL.txt and a CREDITS line.
  3. Tokens. Add ui-palette.gpl, c.phone.*, c.map.* and c.hud.* tokens, plus a validator check that UI code uses no raw hex.
  4. UI-kit molecules. Plate, label card, pill, block row, app tile and badge, each with default, focus, pressed, disabled and locked states and unit tests.
  5. PhoneScene. Frame, status bar, home grid, dock, a 4-step slide-up over 250ms, haptic through platform, buzz-wiggle edge icon, P key, HUD button and touch.
  6. Three apps. Chats (list and thread, over PhoneManager), UPI (balance and ledger) and Maps (opens a placeholder for the P6b fullscreen map).
  7. Verify. Tests green, a playground preset, a phone-frame smoke test (safe areas, 48pt targets, landscape), then stop for your audit.
