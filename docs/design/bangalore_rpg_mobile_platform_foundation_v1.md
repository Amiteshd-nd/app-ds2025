# NAMMA OUTBREAK — Mobile Platform Foundation (Android + iOS) v1.0
Updated: 2026-10-11 · Decision: ADR-64 · Read after `bangalore_rpg_technical_architecture_v1.md`

> **One codebase. Mobile-ready from day one. Shipped web first, then Android, then iOS.**
> We do NOT build three apps. We build one Phaser/TypeScript game and wrap the same `dist/` build in native shells with Capacitor.

---

## 1. The principle: "simultaneous foundation, sequential shipping"

| What happens in parallel (from P0) | What stays sequential |
|---|---|
| Platform abstraction layer (`src/platform/`) | Public web release first |
| Touch-first input, safe areas, orientation, audio unlock | Android store release (after web slice is fun) |
| Native-safe save storage | iOS store release (after Android is stable) |
| Phone smoke test at every audit gate | Store listings, IAP, push notifications |

Why this cuts workload: every mobile problem (notch, touch, audio, storage, backgrounding, performance) gets solved **once, while the feature is being built**, instead of retrofitting 9 phases of code later. Retrofitting is where solo projects die.

What we reject: native rewrites (Swift/Kotlin), React Native, Flutter, Unity port. All of them mean a second codebase. Phaser in a WebView runs this 32-bit game comfortably.

## 2. Stack

| Layer | Choice | Notes |
|---|---|---|
| Game | Phaser 3.90 + TS 5.9 strict (unchanged) | Same code on all 3 platforms |
| Web | Vite + vite-plugin-pwa (unchanged) | Priority 1 |
| Native wrapper | **Capacitor** (current stable at time of setup) | MIT. Generates real `android/` and `ios/` projects from `dist/` |
| Android build | Android Studio + Gradle | Play Console: one-time fee |
| iOS build | Xcode on macOS | Apple Developer Program: yearly fee. **Needs a Mac** — or a cloud macOS CI (GitHub Actions macOS runners / Codemagic) |
| Native plugins | Official `@capacitor/*` only by default: app, preferences, filesystem, haptics, status-bar, splash-screen, screen-orientation, network, share | Third-party plugins need an MIT/Apache licence check (golden rule 5) |

Alternatives considered: **TWA** (Trusted Web Activity) is Android-only and leaves iOS unsolved → Capacitor covers both with one wrapper. Cordova → legacy. Store-submitted bare PWA on iOS → not possible.

Claude Code: verify current Capacitor + platform versions with `npm view` at setup time; pin exact versions in `package.json`.

## 3. Repo structure (additions only)

```
/src/platform/
  Platform.ts          ← the interface (the ONLY thing game code imports)
  web.ts               ← browser implementation
  native.ts            ← Capacitor implementation
  index.ts             ← picks one at boot via Capacitor.isNativePlatform()
/android/              ← generated by `npx cap add android`, committed
/ios/                  ← generated by `npx cap add ios`, committed
capacitor.config.ts    ← appId, appName, webDir: 'dist', splash, orientation
/assets/_meta/platform.json  ← icon/splash source paths, min OS versions
```

npm scripts:
```
build:web     → tsc --noEmit && vite build
cap:sync      → npm run build:web && npx cap sync
cap:android   → npm run cap:sync && npx cap open android
cap:ios       → npm run cap:sync && npx cap open ios
test          → unchanged (117 tests must stay green)
```

## 4. The platform abstraction layer (atomic architecture fit)

In the atomic SYSTEMS tree, `Platform` is an **organism** (like AudioSystem). Each capability is a **molecule**. Game code never calls `navigator.*`, `window.localStorage`, `indexedDB` or `Capacitor.*` directly — the validator/lint fails if it does outside `src/platform/`.

```ts
export interface Platform {
  kind: 'web' | 'android' | 'ios';
  storage:   { get(key): Promise<string|null>; set(key, val): Promise<void>; remove(key): Promise<void>; };
  saves:     { read(slot): Promise<SavePayload|null>; write(slot, p): Promise<void>; export(): Promise<Blob>; import(f): Promise<void>; };
  lifecycle: { onPause(cb): void; onResume(cb): void; onBackButton(cb): void; };   // Android back = pause menu
  haptics:   { tap(): void; impact(level: 'light'|'medium'|'heavy'): void; };         // respects Settings toggle
  display:   { safeArea(): Insets; lockLandscape(): Promise<void>; hideStatusBar(): void; };
  network:   { isOnline(): boolean; onChange(cb): void; };                           // City Pulse bundle fetch
  share:     { image(dataUrl, text): Promise<void>; };                                // City Moments camera
  audio:     { unlock(): Promise<void>; };                                            // first-tap unlock
  // LATER (behind feature flags, not in slice): notifications, iap, analytics
}
```

Rules:
- Each implementation is small and boring. If a feature has no native equivalent, `native.ts` falls back to the web version.
- Feature flags in `data/atoms/flags/platform.json` (e.g. `haptics: true`, `iap: false`). Turning a platform feature off = one atom.
- Tests: mock `Platform` in unit tests so the 117 tests never depend on a device.

## 5. Mobile-ready rules — apply from P0 onward (web phases included)

These are cheap now, expensive later. Claude Code checks them at every audit gate.

**Input**
1. Touch-first. Virtual joystick (side/size from Settings) + context action button. Keyboard and Gamepad API mapped to the same actions via one input map — no per-device logic in scenes.
2. No hover-dependent UI anywhere. Every hover state has a tap equivalent.
3. Tap targets ≥ 48 px logical (multiple of the 8px UI grid; meets iOS 44pt / Android 48dp).

**Screen**
4. Landscape-locked game; Title/Settings tolerate portrait gracefully (show "rotate your phone" panel, not a broken layout).
5. Safe-area insets (notch, Dynamic Island, gesture bar) applied to HUD, minimap, joystick, phone overlay. Use `env(safe-area-inset-*)` on web, `display.safeArea()` on native.
6. Integer scaling + `roundPixels` stays (design system). Letterbox with `c.ui.letterbox` token, never stretch.
7. Test aspect ratios: 16:9, 19.5:9 (modern phones), 4:3 (iPad), 20:9 (tall Android).

**Audio**
8. Nothing plays before first user tap (iOS/Android autoplay rules). Title screen "Tap to start" doubles as `audio.unlock()`.
9. Ship audio as **both** `.m4a` and `.ogg`; Phaser picks what the device supports.
10. Pause all audio on `lifecycle.onPause`; resume on resume.

**Lifecycle & saves**
11. App backgrounded → autosave + pause menu + mute. This is in addition to the ADR-63 autosave triggers.
12. **Saves on native go to the Filesystem/Preferences plugin, not IndexedDB.** iOS WebView storage can be evicted by the OS under storage pressure; losing a save is unforgivable. Web keeps IndexedDB + lz-string. Same `SavePayload`, same version migrations, same export/import format across all three — a save exported on web imports on the phone.
13. Android hardware/gesture back button → open pause menu (never quit the app silently).

**Performance (low-end Android is the floor)**
14. Keep existing budgets: ≤8 MB atlases per district, lazy-load per pocket, baked shadows, no normal maps, EasyStar throttled 500 ms.
15. Texture pages ≤ 2048×2048 (safe on older mobile GPUs).
16. Target 60 fps, accept a stable 30 fps on the low-end test device; never fluctuate. Optional "Battery saver" setting caps at 30.
17. Memory: unload previous pocket's atlas on transition.

**Offline & content**
18. Native builds bundle all core assets in the app (playable fully offline, no first-launch mega-download).
19. City Pulse bundles stay **data only** (JSON + references to art already in the app). Never download executable code — this keeps us inside App Store rules on remote code.

## 6. Phasing (slots into the existing P0–P9 plan)

| When | Mobile work | Gate |
|---|---|---|
| **P0.4 Platform shell** (new, part of P0) | `src/platform/` interface + `web.ts`; Capacitor init; `npx cap add android` + `ios`; empty game boots on Android emulator + iOS simulator from the same `dist/` | Title screen visible on all 3. Tests green. |
| **P1–P2** | Safe areas + landscape lock + audio unlock on Title & Character Creation | Form usable with on-screen keyboard on phone |
| **P3** | Virtual joystick + action button final; `native.ts` storage/saves | M0 loop playable by touch on a low-end Android |
| **P6** | Phone overlay/minimap/settings respect safe areas; haptics + back button | Settings toggles work on device |
| **Every gate P1–P9** | Smoke test: 1 low-end Android device + iOS simulator (or device if available) | Logged in AUDIT_LOG as "mobile smoke: pass/fail" |
| **M1 — Android release** (after web slice is fun & public) | Icons/splash, Play Console listing, Data Safety form, IARC rating, internal → closed test track | Closed testers play Acts 0–1 |
| **M2 — iOS release** (after M1 stable) | Xcode signing, privacy nutrition label, TestFlight → App Store review | TestFlight build passes review |
| **M3 — Platform extras** (later) | Push notifications (City Pulse "this week in the city"), store IAP if a monetization model is chosen, cloud save | Separate ADRs required |

Priority order is preserved: web never waits for mobile; mobile never needs a rewrite.

## 7. Store policy checklist (decide before M1/M2)

- **Digital purchases:** on iOS, any digital unlock (cosmetics, chapters) must use Apple In-App Purchase; Google Play similarly requires Play Billing for digital goods. Monetization model is still open — design so payments are a `platform.iap` molecule behind a flag. Sponsor banners (City Pulse, ADR-56) are ads, not purchases.
- **Tracking / privacy:** City Pulse aggregate heatmaps must be disclosed (Play Data Safety, Apple privacy label). If any tracking links data across other companies' apps or for ads, iOS requires the App Tracking Transparency prompt. Simplest path: first-party, aggregate, consented, no ad SDKs in v1. Ties to the still-open privacy decision.
- **Age rating:** IARC questionnaire (Play) + Apple age rating; aim matches the 16+ framing.
- **Remote content:** City Pulse = data bundles only (rule 19).
- **Minimum functionality:** a full game clears Apple's "not just a website wrapper" bar, but the app must feel native: no browser chrome, no external links for core flows, proper splash/icon, offline play.
- **Brands:** parody rule applies doubly — stores react to trademark complaints faster than the web.
- Claude Code: re-check current Apple App Review Guidelines and Google Play policies at M1/M2 time; they change.

## 9. New risks (extends risk register; numbering continues)

27. **iOS evicts browser storage → lost save** (M/H). Prevent: rule 12, native filesystem saves. Recover: export/import file; cloud save in M3.
28. **No sound on mobile** (H/M). Prevent: rule 8–9. Detect: smoke test. Recover: route all audio start through `audio.unlock()`.
29. **App Store rejection** (remote code, wrapper feel, IAP rules) (M/M). Prevent: §7. Recover: fix cited guideline, resubmit; web and Android unaffected.
30. **Android WebView fragmentation / old GPU** (M/M). Prevent: rules 14–17, low-end test device. Recover: lower texture size, disable post-FX via `grade()` quality flag.
31. **HUD under notch / gesture bar** (H/L). Prevent: rule 5. Recover: one safe-area fix in the HUD organism.
32. **Mobile code leaks into game logic** (`if (isIOS)` scattered in scenes) (M/H). Prevent: all platform calls through `src/platform/`; lint rule. Recover: move the call into a Platform molecule.
33. **No Mac for iOS builds** (M/M). Prevent: decide early — borrow/buy a Mac or use cloud macOS CI. Recover: ship Android first (already the plan).
34. **Mobile work blocks web progress** (M/H). Prevent: mobile is a *smoke test* at gates, not a phase blocker, until M1. Recover: log mobile bug in TASKS "Next", continue web.
