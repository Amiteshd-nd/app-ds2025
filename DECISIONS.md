# Decisions (ADR log, append-only)
Updated: 2026-10-11
ADR-01..64 live in `docs/design/bangalore_rpg_design_decisions_v1.md` (the "why" of the whole design). This file continues the numbering with decisions made **in the repo** during the build. Supersede, don't delete: add a new row "ADR-xx supersedes ADR-yy". Rows marked *(proposed)* await the user's yes/no at the next audit.

| ID | Date | Decision | Why | Rejected alternative |
|---|---|---|---|---|
| ADR-65 | 2026-10-11 | Design docs copied verbatim into `docs/design/`; root holds only the 5 working docs + `AUDIT_LOG.md` | `project_docs_convention.md`: reference, don't copy; settled docs are never rewritten | Pasting design content into root docs |
| ADR-66 *(proposed)* | 2026-10-11 | Content and assets stay under `src/` (`src/data/**`, `src/assets/{tilemaps,tilesets,sprites}`), discovered by `import.meta.glob`. The design docs' root paths (`data/`, `maps/`, `assets/`) map 1:1 onto these | Bundler-resolved URLs work standalone and when the game is consumed as a library; validators and loaders already wired; zero churn before P1 art | Moving to root `data/`+`maps/` (breaks `?url` imports, large rename for no runtime gain) |
| ADR-67 *(proposed)* | 2026-10-11 | Tiled layer taxonomy stays `Ground → Walls → Objects → Collision → Above Player → Effects → Foreground` (`maps.manifest.json#layerOrder`), plus object layers `Spawns`, `Objects Layer`. Design-doc names map onto it: ground=Ground, ground_detail+props_below=Walls/Objects, props_above=Above Player, npc_spawn=Spawns; `pulse_slots` added as an object layer when City Pulse lands | `WorldScene` reads `layerOrder` from the manifest, so a rename is a data edit later, not a code change; both existing maps + generator + validator already use this | Renaming now, before P1 replaces the maps anyway |
| ADR-68 *(proposed)* | 2026-10-11 | Package/app name stays `Namma Quest` until the title decision (unfinished_business "Game title"); docs use the working title NAMMA OUTBREAK | Renaming package, PWA manifest, save key and HUD twice is waste | Renaming to Namma Outbreak now |
| ADR-69 | 2026-10-11 | One `WorldScene` renders every place from a `districts.json` entry; `AirportScene`/`WhitefieldScene` deleted. Saves persist `{districtId, x, y}` (v1.2.0) with migrations from 1.0.0/1.1.0 scene names | Tech architecture §0/§7 steps 1–4; kills the `PGScene` dead-end class of bug; a save survives any change to how a place is drawn | Third hand-written scene; persisting scene keys |
| ADR-70 | 2026-10-11 | Every area edge goes through `TransitScene` (fade-to-black; ride card for bus/metro/cab/scooter, plain fade for walk), driven by the exit's data | Design system §7 motion rule once, not per scene; later rides (window parallax, hotel nights, office time-lapse) extend it without touching WorldScene | Per-exit transition code |
| ADR-71 | 2026-10-11 | Exits are zones first: `zone:reached` is emitted before the destination's `unlock` rule is checked; district gating = `unlock{quest, reputation, flags}` evaluated by `ReputationManager.canEnter`; quests set generic `on_complete.set_flags` (the `unlock_scene` field is retired and rejected by the validator) | The arrival quest's last objective is "reach the exit"; emitting first lets the quest complete and open the gate in one step. Flags are the one unlock currency for districts, dialogue and phone apps | Separate "exit" and "trigger" zones; quests naming scenes |
| ADR-72 | 2026-10-11 | Only `TitleScene › Continue` restores a save; `WorldScene` never hydrates from disk. Autosave on district entry and on scene shutdown | The old scenes called `restore()` in `create()`, so New Game silently inherited the previous run's stats; entry autosave means closing during a transit card resumes at the arrival, not on the exit zone (ADR-63 "autosave on area transition") | Restore-on-create |
| ADR-73 | 2026-10-11 | Ambient crowds, NPC placement and data-placed objects are district data (`ambient`, `npcs`, `objects`); behaviours are named molecules in `src/world/behaviours/` (`BEHAVIOUR_NAMES` kept Phaser-free so the validator can import it) | Atomic architecture: district references ids, never inline copies; adding a mechanic = one molecule + a name in data | Per-scene bot/NPC code |
| ADR-74 | 2026-10-11 | Validators have two channels: **problems** fail the build (anything the engine would mis-load or the player could never reach), **warnings** print and pass (design nits: door not 32×48, ADR-40 density). `validateWorld` cross-checks districts against maps and walks exits from `START_DISTRICT` | A renamed spawn or an unreachable district is silent at runtime; a mis-sized door is a Tiled fix, not a broken build | Everything fatal (blocks P1 art iteration) / everything advisory (dead ends ship) |
